## Plan Summary

Remove LangGraph from CompSynth's orchestration layer by replacing the graph builder with a plain async pipeline function. The implementation must preserve the current node behavior, state merge behavior, no-new-content routing, CLI output behavior, and package verification commands.

Recommended path: implement `src/comp_synth/orchestration/pipeline.py`, update imports, remove `src/comp_synth/orchestration/graph.py`, regenerate `uv.lock`, and update tests/docs so `langgraph` no longer appears outside historical design/plan documents.

## Premises

1. The current graph is a fixed pipeline with one branch after deduplication.
2. The codebase does not currently use LangGraph checkpointing, persistence, graph concurrency, or human-in-the-loop features.
3. Plain async Python is easier for contributors to inspect and test here.
4. State updates must preserve LangGraph's accumulated partial-dict behavior.
5. Dependency removal is incomplete unless `pyproject.toml`, `uv.lock`, runtime code, tests, and docs all stop depending on LangGraph.

Premise gate result: accepted. These match the code in `src/comp_synth/orchestration/graph.py`, `src/comp_synth/main.py`, and `tests/test_pipeline_nodes.py`.

Risk if wrong: if external package users rely on `build_pipeline()`, deleting `graph.py` is a breaking change. The repo itself only imports `build_pipeline()` from `main.py`, so this is acceptable for a pre-1.0 package if documented.

## Engineering Review

### Scope Challenge

The core code path is small enough for sequential implementation. The only hidden complexity is state merging: LangGraph currently accumulates partial dicts returned from each node. The plain pipeline must mirror that by calling `state.update(...)` after every node.

### Architecture Diagram

```text
src/comp_synth/main.py
  imports
src/comp_synth/orchestration/pipeline.py
  default_pipeline_state()
  route_after_deduplicate()
  run_pipeline()
    -> nodes.fetch_sources(state)
    -> nodes.deduplicate(state)
    -> route_after_deduplicate(state)
       -> "end"            : return state
       -> "use_last_digest": state.update(use_last_digest(state)); return state
       -> "summarize"      : continue
    -> nodes.summarize(state)
    -> nodes.enrich(state)
    -> nodes.publish(state)
```

### Implementation Steps

1. Add `src/comp_synth/orchestration/pipeline.py`.
   - Move `_has_last_digest()` and `route_after_deduplicate()` into it.
   - Add `default_pipeline_state() -> PipelineState`.
   - Add `async def run_pipeline(initial_state: PipelineState | None = None) -> PipelineState`.
   - Use `dict(default_pipeline_state())` or an equivalent fresh object so list/dict defaults are not shared across runs.

2. Update `src/comp_synth/main.py`.
   - Import `run_pipeline` instead of `build_pipeline`.
   - Replace `pipeline = build_pipeline()` and `await pipeline.ainvoke(...)` with `await run_pipeline()`.
   - Keep existing logging and return behavior unchanged.

3. Remove LangGraph module usage.
   - Delete `src/comp_synth/orchestration/graph.py` if no tests or runtime imports remain.
   - Do not keep a compatibility shim unless implementation finds a real repo-local caller.

4. Update types and docs.
   - Change `PipelineState` docstring in `state.py` from LangGraph wording to plain pipeline wording.
   - Update `CLAUDE.md` and `docs/Architecture.md`.

5. Remove dependency.
   - Delete `"langgraph>=0.2"` from `pyproject.toml`.
   - Run `uv lock`.
   - Verify `uv.lock` no longer contains LangGraph packages unless a remaining dependency pulls them transitively.

6. Update tests.
   - Change imports from `comp_synth.orchestration.graph` to `comp_synth.orchestration.pipeline`.
   - Keep the existing `route_after_deduplicate()` test.
   - Add tests for `run_pipeline()` branches using monkeypatched node functions:
     - new items route calls `summarize -> enrich -> publish`.
     - no new items plus last digest calls `use_last_digest` and stops.
     - no new items and no last digest returns without calling summarize/publish.
     - partial dict returns are accumulated into final state.

### Code Quality Review

No DRY issue if the pipeline directly calls existing nodes. A local step runner would create unnecessary abstraction and is explicitly out of scope.

Naming decision:

- Use `pipeline.py`, not `graph.py`.
- Use `run_pipeline`, not `build_pipeline`.
- Use `default_pipeline_state` so CLI and tests share the same initial shape.

### Performance Review

No runtime performance risk is introduced. Removing graph compilation slightly reduces startup work. The pipeline remains sequential, matching current behavior.

Do not add concurrency in this change. Fetch concurrency belongs in `ContentManager`, not in orchestration.

### Parallelization Strategy

Sequential implementation, no parallelization opportunity. The runtime code, tests, dependency lockfile, and docs are coupled enough that parallel worktrees would create more merge overhead than value.
